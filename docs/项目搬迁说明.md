## 二、搬到本地：要求、方案与注意事项

### 2.1 环境要求

| 项目 | 要求 |
|---|---|
| JDK | **17**（AGP 8.9.2 推荐；不要用 21+，易报 desugar / jlink 相关错误） |
| Android SDK | Platform 35、Build-Tools 35.0.0 |
| Gradle | 8.11.1，由 wrapper 自动下载，无需手动装 |
| AGP / Kotlin | 8.9.2 / 2.1.20（已在构建脚本中声明） |
| 磁盘 | 项目约 3 GB（含 build 缓存）+ SDK 约 6 GB |
| 系统 | macOS / Windows / Linux 均可 |

### 2.2 两条迁移路线

**方案 A：克隆仓库（推荐，保留完整提交历史）**

```bash
git clone https://github.com/stonewd111/elderly-reminder-app.git
cd elderly-reminder-app

# 补入签名文件（从搬迁包里拷出来）
cp /path/to/elderly-release.jks app/

# 写 SDK 路径
echo "sdk.dir=/Users/你的用户名/Library/Android/sdk" > local.properties

./gradlew :app:assembleRelease
```

**方案 B：只用搬迁包（不联网拉代码）**

```bash
unzip 老人提醒助手-本地迁移包-20261112.zip
cd 老人提醒软件
cp local.properties.example local.properties   # 再改成你的实际路径
./gradlew :app:assembleRelease

# 需要历史时再关联远端
git init
git remote add origin https://github.com/stonewd111/elderly-reminder-app.git
git fetch origin main
git reset --hard origin/main   # 注意：会覆盖工作区，先确认没有本地改动
```

### 2.3 本地路径写法

```
macOS   : sdk.dir=/Users/你/Library/Android/sdk
Linux   : sdk.dir=/home/你/Android/Sdk
Windows : sdk.dir=C\:\\Users\\你\\AppData\\Local\\Android\\Sdk
```

Windows 下必须转义反斜杠和冒号，否则 Gradle 解析失败。

### 2.4 构建产物与校验

```
产物：app/build/outputs/apk/release/app-release.apk
```

校验签名（务必做一次）：

```bash
apksigner verify --print-certs app/build/outputs/apk/release/app-release.apk
```

应输出：

```
证书 SHA-256: 46e1b8f8ffd2725d6377308ff4ab72295e3d26fad2acb29f38003c626289c5ad
v1 scheme (JAR signing): true
v2 scheme (APK Signature Scheme v2): true
```

**`v1 scheme` 必须是 true**。AGP 对 minSdk ≥ 24 默认只打 v2，本项目在 `build.gradle.kts` 里显式开了 `enableV1Signing`，缺失会导致部分 OPPO/老机型安装时提示「没有签名文件」。

### 2.5 必须遵守的注意事项

1. **签名文件不可替换、不可重新生成**。一旦换 key，只能让老人卸载重装。
2. **`versionCode` 必须递增**。当前 39，下一版 40，否则手机上装不上（提示降级）。
3. **`local.properties`、`*.jks` 不要提交**。`.gitignore` 已排除，别用 `git add -f` 强行加。
4. **首次构建需联网**下载 Gradle 发行包与 Maven 依赖；之后可离线构建。
5. **大文件限制**：GitHub / Gitee 单文件上限 100 MB。现有最大文件 aar 39 M 安全，不要再往仓库里塞更大的模型或安装包。
6. **不要在构建脚本里改签名口令**除非同步更新本说明；口令是 `elder2026`，别名 `elder`。
7. **修改 SDK 版本要谨慎**：targetSdk 35 涉及前台服务、全屏通知等权限行为，降级或升级都可能影响闹钟可靠性。

## 三、云端与本地如何协同

### 3.1 基本规则

```
动手前：git pull
收工后：git add … && git commit -m "…" && git push
```

同一时间只让一方改同一个文件，否则要手工解冲突。两边都改了就 `git pull --rebase`，冲突文件逐个处理后再 `git rebase --continue`。

### 3.2 分工建议

| 场景 | 建议做法 |
|---|---|
| 只让云端改（AI 协助开发） | 云端改完 push，本地 `git pull` 拿代码，本地只负责构建/装机 |
| 只让本地改（你手动调 UI 等） | 本地 commit + push，云端 `git pull` 后再动手 |
| 两边并行 | 建分支：`git checkout -b feature/xxx`，完成后合并到 `main` |
| 发版 | 本地或云端都可，但**版本号只能改一次**，改完立刻 push，避免两边各改一次 |

### 3.3 两个远端的同步

- GitHub 是主库，Gitee 是镜像（国内访问快）
- 云端工作区一次 push 同时推两个远端
- 本地只需配一个 origin，建议 GitHub；需要 Gitee 时再加一个 remote

### 3.4 发布流程

1. 改 `versionCode` / `versionName`
2. `./gradlew :app:assembleRelease`
3. `apksigner verify` 确认 v1/v2 双签名
4. 打 tag 并推：`git tag v1.x.x && git push origin v1.x.x`
5. 建 GitHub Release，上传 APK
6. 传一份到飞书云空间「嘟嘟点卯-安装包」，发链接给手机安装

## 四、安全提醒

### 4.1 已存在的风险点

| 风险 | 现状 | 建议 |
|---|---|---|
| 仓库 URL 内嵌明文 token / 密码 | `git remote -v` 可直接看到 GitHub PAT 与 Gitee 密码 | 换机器时**不要复制 `.git/config`**，重新 clone 后改用 SSH 或凭据管理器 |
| 凭据已在对话中出现过 | GitHub PAT、Gitee 密码均出现在聊天记录 | 到 GitHub / Gitee 后台**重新生成**并吊销旧凭据 |
| 签名口令明文写在 `build.gradle.kts` | `storePassword = "elder2026"` | 可接受，但因此**仓库不建议设为公开**；更严谨的做法是改用环境变量或 `local.properties` 注入 |
| 仓库当前为公开 | 源码、模型、文档所有人可见 | 若在意，改回私有；私有后 Release 下载需登录 |
| 云端 SSH 私钥 | 本次在云工作区生成过 `~/.ssh/id_ed25519` | Gitee 已静默添加但**云端 22 端口被封，实际不可用**；可在 Gitee 后台删除，或留作备用 |

### 4.2 推荐的安全配置（本地）

**用 SSH 代替 token**

```bash
ssh-keygen -t ed25519 -C "your@email"
# 公钥加到 https://github.com/settings/keys 和 https://gitee.com/profile/sshkeys
ssh -T git@github.com      # 看到 Hi <用户名>! 即成功

git remote set-url origin git@github.com:stonewd111/elderly-reminder-app.git
```

**签名口令改为外部注入（可选，更安全）**

在 `local.properties` 里写 `SIGN_PWD=elder2026`，构建脚本用 `Properties` 读取，避免口令进版本库。

### 4.3 备份策略

| 对象 | 频率 | 位置 |
|---|---|---|
| `elderly-release.jks` + 口令 | 一次 + 永久保留 | 网盘 + U 盘各一份（**最重要**） |
| 源码 | 每次 push | GitHub + Gitee 双远端 |
| APK | 每次发版 | GitHub Releases + 飞书云空间 |
